# 第 5 周：静态分发与动态分发对比

## 静态分发
静态分发是编译器在编译阶段就可以确定具体类型，会按照`trait`的具体实现结构生成对应的函数，然后直接调用对应结构对于该`trait`的实现方法。适用于，不需要运行时动态判断，具体实现比较少的情况

## 动态分发
具体实现是在运行时通过虚拟函数表间接调用具体实现的，Trait object 的作用是隐藏具体类型，让程序能够通过统一的 trait 接口使用不同的具体实现，并在运行时动态选择需要调用的方法。适用于需要在运行时才能决定对应实现时使用。
`dyn Filter`大小仍无法在编译期确认，只有对应的借用或者`Box`可以确认这些间接对象的大小

## 性能与代码体积
因为静态分发在编译期就生成了具体实现函数，因此提供了直接的调用方式，不需要像动态分发那样还需要虚拟函数表间接调用，因此也更容易发生内联，静态分发会对具体类型单态化，但是由于针对每个具体实现，都需要生成对应的函数，因此生成的机器码就会变大，对于CPU指令缓存的影响可能会较高。
`&dyn Filter`不会产生堆分配，但容器可能会发生堆分配

## LogLens 的选择
当前使用`&impl Filter`，`Filter`的具体实现不多，目前可见的可能就几种，而且在编译期都可以确定，不需要动态判断。目前没有插件化要求，也不存在异构过滤器集合。

## 验证证据
- 静态实验签名：`fn scan_log(path: &str, filter: &impl Filter) -> Result<(), AppError> `
- 动态实验签名：`fn scan_log(path: &str, filter: &dyn Filter) -> Result<(), AppError> `
- 单元测试结果：38 passed
- CLI 集成测试结果：16 passed
- 接口审查后，`OrFilter` 保持模块私有；由于当前 CLI 尚未提供 OR 组合语义，以局部 `#[allow(dead_code)]` 记录有意保留状态。四项质量门禁全部通过。
