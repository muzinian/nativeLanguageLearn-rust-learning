# 在现有课时安排内培养 Rust 工程参与与独立模块开发能力

本次课程审查以 Rust 入门后能参与真实工程、独立开发边界明确的模块为目标，所需领域知识视为已具备或由任务提供，不把编译、网络服务、基础组件、OS 内核或数据库内核等岗位背景纳入完整培养范围。学习者满意当前总课时安排，因此本次审查保留该安排，不以延长课程或增加岗位专业课程作为默认解决方案。学习者于 2026-08-27 确认整体共识并授权更新正式计划，调整落实于 [RUST_TEACHING_PLAN.md v1.2](../../RUST_TEACHING_PLAN.md)，保留已有课程与学习成果。

## 学习者背景

学习者自述已能完整交付功能模块，并独立开发常见应用系统；此背景不包含操作系统、数据库或编译器等系统软件的独立开发能力。该信息用于区分已有的应用工程经验与待学习的 Rust 能力，不作为任何 Rust 知识点已经掌握的验收证据。

## 已确认的教学方式

保留 Rust 核心机制的“先教后用”，在中后期加入独立资料练习：所需语言机制已经学习，但具体 API 或库未由教师讲授，由学习者查文档、做最小实验并应用，教师负责纠偏和评审。此选择在基础讲解责任与独立学习训练之间划定边界，避免将所有新接口都永久限定为教师先讲，也避免以独立学习为由跳过核心机制讲解；正式计划的教学原则、单次流程与对话协议采用同一边界。

## 已确认的能力深度

本阶段必修目标是使用安全 Rust 独立开发模块，能够解释所有权、错误、资源与并发边界。unsafe 与 FFI 的用途、安全责任及阅读注意事项纳入认识范围，但独立编写底层 unsafe 封装或复杂 FFI 实现作为进阶选修，不设为本阶段结课门槛。

## 实施与取舍

- 在原有课次中明确核心机制及先修关系；第 5 周后置集合专题保留，第 6 周从重复实现改为错误与管线迁移。
- 在原有第 8、12、16 周任务内分别安排陌生模块修复、独立模块练习、独立交付与迁移验收，不额外新增完整项目。
- 保留 Linux 性能诊断主线，工具围绕同一问题使用；高级硬件分析等列为选修，避免挤占基础实操。
- 独立开发与迁移是结课硬门槛，不被加权总分或代码产出比例抵消；课时结束仍有缺口时如实记录，不擅自加课或降低要求。
- 本次只更新课程文档，不变更练习实现、不回填学习状态、不自动提交或推送。
