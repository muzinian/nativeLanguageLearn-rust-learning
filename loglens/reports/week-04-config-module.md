# 第 4 周配置模块阅读笔记

## 当前 LogLens 的模块边界

<!-- config、main、matcher 各自负责什么？ -->
`config`模块用来解析配置文件并合并 default / file / CLI 的候选值决议最终的参数值
`main`负责解析`cli`参数并调用其他模块完成任务
`matcher`负责匹配工作
## 配置错误策略
`ConfigError`表达的是配置内容解析错误和配置文件读取错误，不应该很命令行使用是否正确相关。`main`是应用的主题，它最终根据各个模块的返回决定合适的退出码

## 当前不拆 env.rs 的理由

<!-- 现阶段只有一个配置字段时，为什么 config.rs 足够？ -->
目前参数数量只有一个，`config.rs`够用了，再增加一个`env.rs`增加了新的模块但是没有太多收益。

## 将来加入环境变量时的演进方式

<!-- 何时需要 env.rs？default / file / env / CLI 的优先级如何表达？ -->
等后续需要环境变量解析，参数很多的时候，分类清晰的时候，使用`env.rs`解析环境变量是可以的。具体的优先级：`default < file < env < cli`
