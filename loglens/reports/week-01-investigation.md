# 第 1 周日志调查
## 调查问题
统计日志中"登录"出现的次数，匹配了几个 Info,Warn 和 Error
## 输入与脱敏声明
- 输入文件：`fixtures/unicode.log`
- 这是教学用脱敏练习样本，不代表生产环境。
## 预测
预测：匹配 2 条； INFO 1 条， WARN 0 条， ERROR 1 条。
## 实际命令
```bash
cargo run -- fixtures/unicode.log 登录
```
## 实际统计
```
INFO 用户登录成功
WARN 用户重试登录
ERROR 用户登录失败
matched: 3
INFO: 1,WARN: 1,ERROR: 1
```
## 代表性证据
INFO 用户登录成功
WARN 用户重试登录
ERROR 用户登录失败
## 人工复核
三条原始记录都包含“登录”；程序输出与原文一致。预测少了一条，因为我只注意到两条中间包含“登录”的记录，漏看了 WARN 用户重试登录。
## 结论
样本中“登录”相关记录共有 3 条， INFO 、 WARN 、 ERROR 各 1 条；因此样本中存在登录失败信号。预测遗漏了 WARN 用户重试登录。
## 当前限制
日志缺少用户标识和时间字段，无法确认重试与失败是否属于同一用户、是否存在先后关系，更不能推断因果关系。后续需要先扩展日志模型与解析能力；在第 5 周加入时间范围过滤后，才能开始表达更具体的查询条件。
